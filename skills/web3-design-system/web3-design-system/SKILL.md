# Web3 Premium Modern Design — дефолтний стиль агента

Цей скіл — не тема оформлення для конкретного бренду, а **система пропорцій і прийомів**, яку
агент застосовує щоразу, коли робить UI, якщо користувач явно не попросив інший стиль. Джерело —
детальний аналіз реальних скріншотів трьох продуктів: megapot.io, feel.cash і Coinbase Wallet
(вебсайт + мобільний застосунок). Усі три — різний бренд і різний акцентний колір (megapot: чорний
+ кольоровий градієнт-текст; feel.cash: синій; Coinbase Wallet: бірюзово-циановий), але одна й та
сама "мова" пропорцій і компонування — саме вона й дає відчуття "дорогого, сучасного web3-продукту".
Цю мову й треба відтворювати з новими кольорами/текстом під кожен проєкт.

**Головне правило: результат ЗАВЖДИ преміальний і сучасний за замовчуванням.** Не питай "який
стиль хочеш" — просто роби в цій системі, якщо не сказано інше. Уникай усього, що виглядає як
"стандартний AI-дизайн 2023 року": фіолетово-рожевий градієнт на всьому, круглі avatar-плейсхолдери
з emoji, картка = білий прямокутник + `box-shadow: 0 2px 4px`, System-font без ніякої ієрархії.

## 1. Антипатерни — чого НІКОЛИ не робити

- ❌ Emoji замість іконок у продуктовому UI (тільки в чат-повідомленнях/неформальному контенті).
- ❌ "Дефолтна" плоска картка: білий/сірий прямокутник, слабка тінь, border-radius 4-8px скрізь.
- ❌ Один шрифт однієї ваги на весь інтерфейс без контрасту в товщині чи стилі.
- ❌ Фіолетово-рожевий "AI-градієнт" як універсальний фон/кнопка.
- ❌ Іконки різних стилів впереміш (частина outline, частина filled, частина emoji).
- ❌ Статичні числа/статуси без жодного руху там, де дані "живі" (лічильники, live-статуси).
- ❌ Однакова заокругленість для геть усіх елементів незалежно від розміру (дивись шкалу в §2).
- ❌ **Увесь контент екрана в одній рамчастій картці по центру** (лого + текст + статус + заголовок +
  кнопки стопкою всередині одного border-картки) — це найпізнаваніший AI-шаблон "coming soon/404".
  Рамчасті картки — для окремих самодостатніх віджетів (countdown, stat-блок), НЕ контейнер для
  всього екрана. Деталі — §9.

## 2. Шкала заокруглень — пропорційна до розміру елемента

Ключове спостереження з обох сайтів: заокруглення НЕ однакове всюди, воно росте разом з розміром
елемента, і найбільші контейнери (hero-картки, промо-банери) заокруглені настільки сильно, що
межують із "blob"-формою — це і є той самий "новітній" ефект, а не типові 8px-кутики.

```
--radius-xs:   8px;    /* дрібні чіпи, теги */
--radius-sm:   12px;   /* маленькі кнопки, badge */
--radius-md:   16-20px; /* стандартні картки, поля вводу */
--radius-lg:   24-28px; /* великі картки, модалки, промо-блоки */
--radius-xl:   32-40px; /* hero-картки, "blob"-контейнери на всю ширину */
--radius-pill: 999px;  /* усі primary-кнопки, nav, badges, segmented control */
```
Правило: чим важливіший/більший елемент — тим сильніше заокруглення (аж до blob).

**Мова форм по типу елемента (підтверджено на Coinbase Wallet, де всі три форми співіснують на
одному екрані):**
- **Pill (999px)** — навігація (bottom nav, tabs), пошукові поля, CTA-кнопки, фільтр-чіпи, segmented
  control, статус-бейджі. Усе, що "клікабельне й горизонтальне".
- **Rounded square (`--radius-md`/`--radius-lg`, 16-24px)** — quick-action плитки (грід іконка+підпис
  типу Deposit/Receive/Send/Trade), картки, app-іконки в списку закладок. Усе, що "контейнер з
  вмістом", а не самостійна кнопка-дія.
- **Circle** — аватари користувачів, іконки монет/токенів, маленькі action-icons (settings, gift).
Не змішуй: quick-action плитка ніколи не pill, а nav-таб ніколи не квадратний.

## 3. Типографічна ієрархія та пропорції

Обидва сайти будують ієрархію на РІЗКОМУ контрасті ваги й стилю, а не тільки розміру:

- **Display/Hero**: дуже жирний (800-900), компактний/трохи конденсований sans, часто з легким
  italic-нахилом для заголовків-"обіцянок" (промо, hero-текст). Розмір — драматично більший за H2,
  не поступове зменшення: якщо H1 — 56px, H2 не 40px, а різкіше — 24-28px. Контраст важливіший за
  плавність.
- **Акцентний serif-italic твіст** — 1-2 фрази на весь продукт (заголовок важливої секції або
  порожній стан), набрані елегантним serif italic (Playfair Display / Canela / class. Times italic),
  коли решта UI — sans. Це навмисний "злам" очікувань, який робить продукт відчутно дорожчим на
  контрасті. Не використовуй частіше — ефект тримається на рідкості.
  variables:
  --font-display: жирний конденсований sans (Anton / Archivo Black / General Sans 800-900), для H1/hero
  --font-accent: елегантний serif italic, для 1-2 фраз на екран
  --font-body: нейтральний sans (Inter/Geist), для всього іншого тексту й UI
  --font-mono: тільки для адрес гаманців/хешів
- **Числа в hero-позиції (сума виграшу, баланс, TVL)**: НЕ однорідна вага. Найзначуща частина числа —
  екстра-жирна, символ валюти й дрібна частина — тонші/легші в тому ж рядку. Це створює візуальну
  ієрархію всередині одного числа без зміни розміру шрифту.
- Для справді "hero" грошових значень (jackpot/головний виграш) можна піти ще далі — метало-хромова
  обробка тексту (градієнт + text-stroke, приклад у §5) — використовуй ощадливо, 1 раз на екран максимум.

Типографічний масштаб (bases, адаптуй під бренд):
```
--text-hero: clamp(2.5rem, 8vw, 6rem);
--text-h1:   clamp(1.75rem, 4vw, 2.75rem);
--text-h2:   1.375rem;   /* різкий стрибок вниз від h1, не плавний */
--text-body: 1rem;
--text-small:0.875rem;
--text-micro:0.75rem;
```

## 4. Ритм відступів і компонування

- Базова сітка — 8px, але великі hero-секції отримують щедрі відступи (48-96px vertical) — простір
  навколо hero-елемента є частиною преміальності, не економ на ньому.
- Один hero-фокус на екран: одне велике число АБО один сильний CTA-блок, не декілька рівнозначних
  акцентів одночасно.
- Багатошаровість зверху сторінки — прийом з обох сайтів: тонка смуга-нотифікація (новина/статус) +
  під нею стрічка живої активності (marquee), яка нескінченно скролиться — це работает як соціальний
  доказ і одразу сигналізує "тут відбувається щось живе, зараз". Використовуй такий двошаровий топ
  скрізь, де є соціальна/транзакційна активність (покупки, виграші, трейди, стейкінг-події).

## 5. Компонент-прийоми (переносити як техніку, кольори — свої)

### Кнопки
Primary — завжди pill, суцільна заливка кольором бренду, glossy/glow-ефект знизу або зсередини
(м'який blur-shadow кольором акценту під кнопкою, не флет тінь вниз). Ніколи прямі кути на CTA.

### Картки
Тонка 1px напівпрозора рамка (не суцільний сірий border), радіус за шкалою §2, hover — легкий підйом
(`translateY(-2px)`) + рамка яскравіша + м'який glow-shadow кольором акценту, transition 150-200ms.

### Segmented control / перемикач режимів
Pill-контейнер, неактивна опція — прозорий фон/сірий текст, активна — біла/контрастна підкладка що
"плаває" всередині з transition на позицію (не миттєва зміна кольору).

### Живий/countdown-індикатор
Пульсуюча кольорова крапка (`animation: pulse`) + м'яке зовнішнє сяйво навколо картки, а не просто
border — сигналізує "це відбувається зараз в реальному часі".

### Хромоване hero-число (опційно, для грошових hero-значень)
```css
.chrome-number {
  font-family: var(--font-display);
  font-weight: 900;
  background: linear-gradient(180deg, #FFFFFF 0%, #CBD5E8 35%, #7F97C4 55%, #FFFFFF 75%, #B9C7E0 100%);
  -webkit-background-clip: text; background-clip: text; color: transparent;
  -webkit-text-stroke: 1.5px rgba(10,14,26,0.85);
  filter: drop-shadow(0 4px 0 rgba(10,14,26,0.5)) drop-shadow(0 10px 24px var(--accent-glow));
}
```

### Marquee-стрічка живої активності
```css
.ticker { display: flex; gap: 24px; white-space: nowrap; animation: scroll-left 22s linear infinite; }
@keyframes scroll-left { from { transform: translateX(0); } to { transform: translateX(-50%); } }
```

### Bottom nav (мобільна версія)
Не full-width бар, а floating pill, підвішений над контентом з відступом знизу; активний пункт —
кольорове коло-підкладка навколо іконки, а не просто зміна кольору іконки.
```css
.bottom-nav {
  position: fixed; bottom: calc(16px + env(safe-area-inset-bottom, 0px));
  left: 16px; right: 16px; border-radius: 999px;
  background: rgba(13,20,32,0.92); backdrop-filter: blur(20px);
  border: 1px solid rgba(255,255,255,0.06);
  display: flex; justify-content: space-around; padding: 10px 8px;
}
```

### Порожні стани
Велика форма-"blob" по центру (не просто ілюстрація), під нею serif-italic заголовок (§3), сірий
sans-підзаголовок, одна pill-кнопка CTA з glossy-заливкою.

### Quick-action grid (Deposit / Receive / Send / Trade — з Coinbase Wallet)
4 (або менше) rounded-square плитки в ряд під hero-числом: іконка зверху по центру, короткий підпис
знизу, темна surface-заливка, БЕЗ рамки. Це головна дія екрана — розташовуй одразу під hero-числом,
до будь-яких списків.
```css
.action-tile {
  display: flex; flex-direction: column; align-items: center; gap: 8px;
  background: var(--dark-surface); border-radius: var(--radius-lg);
  padding: var(--space-4) var(--space-3);
}
```

### Asset list row (рядок токена/монети — патерн з усіх трьох продуктів)
Стандартна структура рядка активу, якою варто користуватись у будь-якому фінансовому списку:
`[аватар-коло з маленьким бейджем мережі в правому нижньому куті] [Назва + verified-бейдж] [сірий
підрядок: маркет-кап/кількість] ..... [ціна bold праворуч] [кольоровий % з трикутником під нею]`.
Праву колонку завжди вирівнюй по правому краю у два рядки (ціна над відсотком), ліву — аватар+текст
в один рядок.
```css
.asset-row { display: flex; align-items: center; justify-content: space-between; padding: var(--space-3) 0; }
.asset-row__avatar { position: relative; width: 44px; height: 44px; border-radius: 50%; }
.asset-row__badge { position: absolute; right: -2px; bottom: -2px; width: 18px; height: 18px;
  border-radius: 50%; border: 2px solid var(--dark-bg); } /* мережевий/статусний бейдж поверх аватара */
.asset-row__change--up { color: var(--success); } .asset-row__change--down { color: var(--error); }
```

### Verified-бейдж — фірмова "блоб"-форма замість кола
Галочка верифікації сидить не в звичайному колі, а в чотирипелюстковій скруглено-зірчастій формі
(squircle/blob), часто з легким градієнтом (циан→блакитний). Використовуй SVG-форму типу
`squircle`/"blob-badge", а не `border-radius: 50%`, для будь-яких verified/trust-індикаторів — це
одразу читається як "не дефолтна іконка з бібліотеки".

### Filter chip row (горизонтальний ряд фільтрів-категорій)
Ряд pill-чіпів під search-баром: іконка + текст всередині кожної, іконки одного акцентного кольору
(не мультиколор), неактивні чіпи — темна прозора заливка, активна — трохи світліша підкладка.
Скролиться горизонтально на мобільному, не переноситься в другий рядок.

### Частинки/зорошний пил на темному hero-фоні (лендінг/промо-екрани)
На великих промо-блоках (не в застосунку, а в лендінгах/banners) додавай ледь помітні статичні
крапки-"пил" (2-4px, opacity 0.15-0.3) розкидані по темному фону навколо hero-заголовка — легкий
"космічний" текстурний шар, який не відволікає, але прибирає відчуття "порожнього флет-фону".

## 6. Кольори — принцип, не палітра

Не копіюй лавандовий/м'ятний/navy/циан з прикладів буквально — обери 1 фірмовий акцентний колір під
конкретний проєкт і застосуй ту саму СТРУКТУРУ (принцип "один акцент" підтверджений на трьох різних
продуктах з трьома різними кольорами — це не збіг, а свідомий підхід):
- Нейтральна база (світла ЧИ темна — підтримуй обидві теми з перемикачем, якщо це застосунок, а
  не одноразовий лендінг).
- Один акцентний колір, що з'являється в кнопках, glow-ефектах, live-індикаторах — і більше ніде.
- Semantic-кольори (success/error) — окремо від акценту, не плутати.
- Для light-теми: пастельна акцентна картка з дуже сильним заокругленням (§2, xl/blob) як "hero-блок".
- Для dark-теми: база темніша за чистий чорний, з ледь помітним кольоровим підтоном (не `#000000` в
  вакуумі).

## 8. Десктоп-специфіка (підтверджено на десктопних версіях усіх трьох продуктів)

Десктоп — це НЕ той самий макет розтягнутий на всю ширину. Ключова відмінність: багато простору
навколо центрального фокус-елемента замість full-bleed заповнення.

- **Кероване обрамлення, не full-bleed.** Buy-tickets картка megapot на десктопі — вузька, по центру
  екрана, з великим порожнім простором навколо (не розтягнута на всю ширину, як на мобільному).
  Той самий принцип для будь-якого модального/формового флоу: фіксована максимальна ширина
  (480-560px для форм, 720-960px для контентних блоків), центрування, а не stretch.
- **Sidebar-навігація замість bottom-nav** для web-застосунків (не лендінгів) — вертикальний список
  іконка+підпис зліва, і десь у сайдбарі — одна viзуально контрастна pill-кнопка головної дії
  (напр. "Launch a coin" — суцільна біла/акцентна pill серед прозорих nav-пунктів). Це "вертикальна
  версія" того самого floating-pill принципу з мобільної нав.
```css
.sidebar-nav { display: flex; flex-direction: column; gap: 4px; width: 220px; padding: var(--space-4); }
.sidebar-nav__item { display: flex; align-items: center; gap: 10px; padding: 10px 14px;
  border-radius: var(--radius-md); color: var(--dark-text-secondary); font-weight: 600; }
.sidebar-nav__item--active { color: var(--dark-text); background: rgba(255,255,255,0.06); }
.sidebar-nav__cta { border-radius: var(--radius-pill); background: #fff; color: #000;
  font-weight: 700; padding: 12px 20px; text-align: center; margin-top: var(--space-3); }
```
- **Card-grid замість list-row для великих колекцій** (коли елементів багато й важлива візуальна
  впізнаваність — токени/монети на маркетплейсі): квадратне зображення зверху з накладеними дрібними
  бейджами в кутку (мережа, verified, платформа — стеком по 2-3 маленькі іконки), назва+бейджі,
  ціна+% нижче, дрібний рядок автор+час внизу картки. Використовуй list-row (§5) для фінансових
  портфелів/балансів, card-grid — для "маркетплейсу" схожих елементів (токени, NFT, продукти).
```css
.item-card { border-radius: var(--radius-lg); overflow: hidden; background: var(--dark-surface); }
.item-card__thumb { position: relative; aspect-ratio: 1; width: 100%; }
.item-card__badges { position: absolute; top: 8px; right: 8px; display: flex; gap: 4px; }
.item-card__badge { width: 20px; height: 20px; border-radius: 50%; border: 2px solid var(--dark-surface); }
```
- **Quantity stepper** (вибір кількості — квитки, суми, ставки): ряд швидких pill-пресетів
  (10 / 50 / 100 / Custom) + окремий степер знизу — кругла мінус-кнопка, велике число по центру,
  кругла плюс-кнопка. Обидва елементи — pill/circle, ніколи не звичайний `<input type=number>`.
- **Decorative orbit rings** — на великих hero-секціях (Coinbase Wallet-подібний лендінг) навколо
  headline можна додати 1-2 тонкі концентричні кола-контури (`border: 1px solid rgba(255,255,255,0.06)`)
  плюс розкидані частинки (§5) — це посилює "космічний/преміальний" ефект темного hero без важкого фону.
- **Layered device mockups** — коли продукт має і web, і mobile, компонуй їх РАЗОМ в одному
  промо-блоці: широка "десктоп"-панель застосунку зверху + телефон-мокап, що частково перекриває її
  знизу-праворуч. Це візуально одразу каже "один продукт, всі платформи" — застосовуй у hero
  лендінгу, якщо в тебе теж є web+mobile.
- **Фірмовий serif/italic твіст працює і в логотипі**, не лише в заголовках — сам wordmark бренду
  може бути написаний елегантним italic/script-шрифтом (як "$Feel"), поки решта UI-суворо технічний
  sans. Розглянь це і для лого проєкту, не тільки для копірайтингу.

## 9. Композиція одного екрана — типові провали агента

Ці правила зʼявились після реального прикладу: агент застосував окремі прийоми скіла (orbit rings,
glow-картка, serif-твіст) технічно правильно, але екран все одно не виглядав "класно", бо порушив
композиційні правила нижче. Кожен провал тут — не про "немає прийому", а про "прийом є, але без фокусу".

- **Акцент має бути ВИДИМИЙ, не лише присутній у токенах.** Недостатньо, щоб `--accent` існував у
  CSS-змінних — хоча б ОДИН елемент на екрані (заливка кнопки, число, іконка, тонка лінія-glow) має
  бути цього кольору, інакше весь екран злипається в сіро-білий градієнт і втрачає фокус, яким би
  преміальним не був сам тон. Якщо, зібравши екран, ти бачиш тільки чорний/білий/сірий — це провал
  §6, навіть якщо чекліст "є акцентний колір у змінних" формально пройдено.
- **Headline — найважливіший елемент, він має це виглядати.** Великий заголовок, набраний просто
  жирним сірим без glow/ваги/градієнта, програє по візуальній вазі навіть маленькій іконці над ним.
  Застосовуй до hero headline щонайменше одне з: вищий контраст кольору з рештою тексту (чистий
  білий, не приглушений сірий), drop-shadow/glow під текстом (§1 megapot-приклад), або масив ваги
  як у §3. Headline, який "тихіший" за елементи навколо нього — завжди помилка.
- **Якщо кнопок 2+, одна ЗАВЖДИ primary.** Дві кнопки однакової візуальної ваги (обидві outline,
  обидві сірі, обидва border) — порушення правила "один hero-фокус" (§4). Завжди признач одну
  суцільно залитою акцентом із glow (primary — найважливіша дія), іншу — outline/прозору secondary.
  Якщо всі дії рівнозначні за змістом — все одно обери одну як візуальний primary, не залишай все
  secondary.
- **Відступи мають ієрархію, не однаковий ритм скрізь.** Якщо gap між КОЖНОЮ парою елементів на
  екрані однаковий (бейдж→іконка→бейдж→заголовок→текст→кнопки йдуть із тим самим інтервалом) —
  це читається як "список", а не як "композиція з фокусом". Дай найважливішим елементам (hero-іконці/
  числу, headline) більше простору навколо, ніж дрібним допоміжним (badges, meta-текст) — нерівний
  ритм відступів сигналізує ієрархію важливості так само, як розмір шрифту.

## 9b. Як агент САМ вирішує розміщення (не ти кожен раз це кажеш)

Все попереднє — словник прийомів. Але "стильно" — це ще й РІШЕННЯ про композицію, яке агент має
приймати сам, до того як почне писати код. Онови собі ось такий внутрішній чекліст на старті
кожного екрана — відповіді на ці 4 питання і визначають, чи вийде "ще один шаблон" чи "стильно":

1. **Що ТУТ головне, і наскільки воно більше за решту?**
   В кожного референсного екрана є один елемент, який очевидно домінує за розміром/вагою (hero-число,
   headline, telefon-мокап) — решта помітно дрібніша. Якщо, дивлячись на макет, не можеш за 1 секунду
   сказати "ось на це я дивлюсь першим" — значить усі елементи одного розміру/ваги, і це провал.
   Збільш головний елемент ще сильніше, зменш другорядні.

2. **Це живе прямо на фоні, чи це самостійний віджет у рамці?**
   За замовчуванням hero-контент (заголовок, головне число, головний CTA) живе ПРЯМО на фоні сторінки
   — без обвідної картки навколо. Рамчасту картку з border/glow застосовуй лише для одного конкретного
   самодостатнього шматка інформації (countdown, prize-card, auth-форма) — не для згортання всього
   вмісту екрана в один контейнер. Якщо ти обгорнув логотип + заголовок + кнопки в одну спільну
   картку "про всяк випадок" — зупинись і прибери рамку, залиш контент прямо на фоні.

3. **Де асиметрія/перекриття замість ідеального центрування?**
   Симетрично-центрований стовпчик (все по центру, однакові відступи) — це дефолтна "AI-розкладка".
   У референсів завжди є хоч один елемент, що порушує сітку: telefon-мокап перекриває край картки,
   marquee-стрічка виходить за межі екрана з обох боків, hero-число асиметрично зміщене. Став собі
   питання: "що в цьому макеті НЕ по центру і НЕ всередині рівного padding?" — якщо відповіді немає,
   додай один елемент, що свідомо порушує симетрію (overlap, bleed за край, зсув).

4. **Чи достатньо "дихання" у головного елемента?**
   Головний елемент повинен мати простір навколо себе, кратно більший за простір між дрібними
   допоміжними елементами (§9, пункт про відступи). Якщо весь контент тулиться до одного padding —
   забери другорядне, дай головному більше повітря.

Став ці 4 питання собі МОВЧКИ перед кожним новим екраном — не питай користувача, що саме розмістити
де; користувач каже ЩО показати (контент, дії), а ЯК розмістити — завжди рішення агента за цим скілом.

## 10. Чекліст перед тим, як здати UI

- [ ] Заокруглення масштабуються за розміром елемента (§2): pill для дій/nav, rounded-square для
      контейнерів/quick-actions, коло для аватарів — форми не змішані.
- [ ] Якщо є списки токенів/активів/транзакцій — використаний asset-row патерн (§5), не довільна верстка.
- [ ] Якщо є головна дія екрана (Deposit/Send/Trade-подібне) — це quick-action grid під hero-числом, не список кнопок.
- [ ] Є різкий контраст ваги/стилю шрифтів (display жирний + 1-2 serif-italic акценти + нейтральний body).
- [ ] Немає жодного emoji як іконки в продуктовому UI.
- [ ] Немає "дефолтної" плоскої картки з border-radius 4-8px і слабкою сірою тінню.
- [ ] Є хоча б один живий/анімований елемент там, де дані динамічні (marquee, pulse, count-up).
- [ ] Один фірмовий акцентний колір, не набір випадкових кольорів — І він реально ВИДИМИЙ на екрані
      (заливка кнопки/число/glow-лінія), не лише в CSS-змінних, поки весь видимий UI сіро-білий (§9).
- [ ] Headline виглядає найважливішим елементом екрана (вага/колір/glow), не тьмяніший за іконки навколо (§9).
- [ ] Якщо кнопок 2+ — одна явно primary (залита акцентом+glow), решта — secondary, не всі однакові (§9).
- [ ] Відступи між елементами нерівномірні за важливістю — hero-елементи "дихають" більше, ніж meta-деталі (§9).
- [ ] Пройдено 4 питання з §9b: є явний домінант за розміром, hero-контент НЕ загорнутий в одну спільну
      картку, є хоч один елемент поза ідеальним центруванням, головний елемент має найбільше "дихання".
- [ ] Hero-числа мають внутрішню вагову ієрархію (не однорідний шрифт).
- [ ] Мобільна версія має власну навігацію (floating pill), а не стиснуту версію десктопу.
- [ ] Десктоп-версія НЕ просто розтягнута мобільна: форми/модалки центровані з фіксованою max-width,
      є sidebar-нав для застосунків, великі колекції — card-grid, а не list-row.
- [ ] Результат НЕ виглядає як типовий AI-згенерований шаблон — якщо є сумнів, додай один сильний
      фірмовий прийом (glow, marquee, chrome-число, serif-твіст) і перевір ще раз.
